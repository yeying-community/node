# 节点架构V2

本文记录 Node 下一阶段开发与联调路线。V2 的核心目标是补齐通行证、主体、授权、设备恢复和 MPC 生产决策能力，使 Node 能稳定承担社区生态中的 Registry / Portal / Passport Provider / Identity Control Plane 定位。

## 当前判断

Node V1 已具备 Passkey、TOTP、中心化 UCAN issuer、应用授权策略、MPC 协调和 custody 加密快照等基础能力。当前已开始按钱包 V2 M2-M5 补齐通行证后端闭环：

| 钱包 V2 阶段 | Node 当前状态 | 主要缺口 |
| --- | --- | --- |
| M2 Passkey 身份登录 | 后端闭环已具备，待 Wallet / Web 联调 | 已实现 `subjectId`、subject 级 Passkey、WebAuthn RP challenge、authorization code + PKCE；待补完整钱包地址证明恢复 UI |
| M3 授权与资源访问收敛 | 部分基础存在 | 缺 scoped grant 持久模型、grant 撤销传播、授权审计、session 级 audience/capabilities 边界 |
| M4 多设备与恢复 | 未满足 | 缺设备目录、设备撤销、manifest 版本、远端回滚检测和恢复演练记录 |
| M5 MPC 生产化决策 | 未满足 | 现有 MPC 只是协调层，缺门限签名实现、安全评审、故障注入和生产准入结论 |

因此 V2 不再新增泛化能力清单，而是围绕 M2-M5 做工程化切片，按“数据模型 -> API -> UI/文档 -> 跨仓库联调 -> 验收测试”推进。

## 设计原则

- Node 继续保持 Registry / Portal / Passport Provider 定位，不拥有 Project 业务权限、Warehouse 文件数据面或 Router 模型计量。
- 认证和授权分离：Passport 解决“是谁”，scoped grant / UCAN 解决“能访问什么”。
- `subjectId` 是社区主体，不应继续等同钱包地址；钱包地址、Passkey、TOTP、设备都只是主体的绑定凭据或认证方式。
- 业务应用只能拿到短期 app session / authorization code / scoped grant，不能把 Node 登录态当成 Router、Warehouse 等资源服务的全权凭据。
- 授权、设备、恢复和撤销必须可审计、可回放、可测试；关键状态不能只保存在内存 Map。
- Runtime 安装、升级、回滚、卸载继续归 Agent Runtime，不回流 Node。

## V2-M2：Passport Identity

目标：Node 作为 WebAuthn RP 和 Passport Provider，支持同一 `subjectId` 同时绑定 Wallet 地址和 WebAuthn Passkey，并通过 authorization code + PKCE 向业务应用分发短期会话。

### Node 交付

#### 数据模型

新增持久表：

| 表 | 目的 |
| --- | --- |
| `passport_subjects` | 社区主体，主键 `subject_id`，记录创建来源、状态、主地址、创建/更新时间 |
| `passport_wallet_bindings` | `subject_id -> wallet address` 绑定，记录链、地址、绑定证明、状态、撤销时间 |
| `passport_passkey_credentials` | `subject_id -> WebAuthn credential`，Passport Passkey 的唯一凭据表 |
| `passport_webauthn_challenges` | 持久化 WebAuthn registration / authentication challenge，支持过期、一次性使用和 request 绑定 |
| `passport_authorization_requests` | 业务应用发起的登录/授权请求，持久化 request、app、redirect、PKCE challenge、状态 |
| `passport_authorization_codes` | 一次性 code，绑定 request、app、redirect、PKCE challenge、subject、过期和使用状态 |
| `passport_audit_logs` | 登录、绑定、恢复、撤销、失败和风险事件审计 |

#### API

新增 `/api/v1/public/auth/passport/*`：

| 接口 | 用途 |
| --- | --- |
| `GET /status` | 返回 Passport、WebAuthn RP、PKCE、issuer 就绪状态 |
| `POST /bind/request` | 已登录钱包创建或复用 `subjectId -> wallet` 绑定 |
| `POST /bind/confirm` | 提交钱包地址证明，确认 `subjectId -> wallet` 绑定 |
| `POST /bind/unlink/request` | 已登录钱包获取社区身份解绑签名消息 |
| `POST /bind/unlink/confirm` | 校验钱包签名，撤销钱包绑定、主体 Passkey、授权请求/授权码并写审计 |
| `POST /passkey/register/request` | 已登录钱包主体生成 WebAuthn registration options |
| `POST /passkey/register/confirm` | 校验 WebAuthn registration response，持久化 `subjectId -> credential` |
| `POST /authorize/request` | 业务应用发起 code + PKCE 登录请求 |
| `GET /authorize/request/:requestId` | 查询授权请求公开信息 |
| `POST /authorize/challenge` | 针对 request 生成 WebAuthn authentication options |
| `POST /authorize/approve` | 校验 WebAuthn assertion 或 Bearer 钱包确认，签发 authorization code |
| `POST /authorize/exchange` | 校验 `code + appId + redirectUri + codeVerifier`，返回 subject/app session/scoped grant |
| `GET /bindings` | 当前 subject 的钱包绑定概览 |
| `GET /passkey/credentials` | 当前 subject 的 Passkey credential 列表 |
| `POST /passkey/credentials/revoke` | 撤销当前 subject 的 Passkey credential |

关键约束：

- WebAuthn 注册和认证必须校验 RP ID、origin、challenge、credential 状态和用户验证结果。
- 日常登录应支持 discoverable credential；不能要求用户先输入钱包地址。
- code 必须一次性、短期、持久化，并绑定 `appId`、`redirectUri`、`codeChallenge`、`subjectId`。
- `authorize/exchange` 必须校验 PKCE `codeVerifier`，不能只靠 `code + redirectUri`。
- 钱包恢复必须要求地址控制证明，并写入审计和安全通知。
- 社区身份解绑必须由 Node 校验钱包签名后执行，不能只删除 Wallet 本地状态；解绑时需撤销当前钱包绑定、该主体下 Passkey credential、未完成授权请求和未使用授权码，并记录审计。

### 联调对象

- Wallet：地址控制证明、绑定确认、恢复确认、Passkey 登录回调适配。
- Wallet：社区身份解绑按钮先调用 `bind/unlink/request`，对返回 `message` 做钱包签名，再调用 `bind/unlink/confirm` 并刷新身份状态。
- Project / Chat：使用 `authorize/request -> approve -> exchange` 获取 app session。
- Node Web：Passport 授权页、绑定页、凭据管理页。

### 完成条件

- 没有钱包插件的新浏览器可以通过 Passkey 登录同一 `subjectId`。
- 错误 origin/RP ID、重放 challenge、缺少用户验证、已撤销 credential、错误 PKCE verifier 均被拒绝。
- 绑定、登录、撤销、恢复均有持久审计记录。

## V2-M3：Scoped Grant 与资源访问收敛

目标：Node、业务应用、Router、Warehouse 共同使用一致、最小、服务绑定且可撤销的能力凭据。

### Node 交付

#### 数据模型

新增持久表：

| 表 | 目的 |
| --- | --- |
| `scoped_grants` | 授权主记录，绑定 `grant_id`、subject、app、audience、capabilities、状态和有效期 |
| `scoped_grant_tokens` | 已签发 token 记录，记录 token id/hash、audience、capability、过期和撤销状态 |
| `scoped_grant_revocations` | grant/token 撤销记录和传播状态 |
| `scoped_grant_audit_logs` | 创建、签发、使用、撤销、失败和管理动作审计 |

#### API

新增或收敛接口：

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/public/auth/grants` | 基于 Passport app session 创建 scoped grant |
| `GET /api/v1/public/auth/grants` | 用户查看授权 |
| `GET /api/v1/public/auth/grants/:grantId` | 查询授权详情 |
| `POST /api/v1/public/auth/grants/:grantId/token` | 为指定 audience 签发短期 UCAN / resource token |
| `POST /api/v1/public/auth/grants/:grantId/revoke` | 撤销 grant |
| `POST /api/v1/public/auth/grants/tokens/:tokenId/revoke` | 撤销单个 token |
| `GET /api/v1/internal/auth/grants/:grantId/status` | Router/Warehouse 独立校验 grant 状态 |

对现有 `/api/v1/public/auth/central/*` 的调整：

- `central/session` 需要记录允许签发的 audience/capabilities，而不是只记录 subject。
- `central/issue` 只能签发 session 允许范围内的子集。
- `central/revoke` 只能作为临时兼容；生产级撤销以 scoped grant 为准。

### 联调对象

- Router：只接受发给 Router audience 的 grant/token，独立校验 `grantId`、audience、capability、过期和撤销。
- Warehouse：只接受受限目录和动作，独立校验 `grantId` 与 capability。
- 业务应用：不得复用单一 Node JWT 访问多个资源服务；按 audience 获取独立短期凭据。
- Wallet：展示授权确认、授权列表和撤销入口。

### 完成条件

- 每个资源请求可追溯至 `subjectId + appId + grantId + audience + capability`。
- 跨服务 token 不能复用。
- grant/token 撤销能在约定时间内被 Router/Warehouse 感知。
- 授权创建、签发、撤销、失败均可审计。

## V2-M4：设备目录与恢复

目标：Node、Wallet 和远端存储共同支持设备目录、远端撤销、回滚检测与恢复演练，且 Node 始终不能恢复钱包私钥。

### Node 交付

#### 数据模型

新增持久表：

| 表 | 目的 |
| --- | --- |
| `passport_devices` | subject 设备目录，记录 deviceId、名称、平台、认证方式、状态、最后使用时间 |
| `passport_device_sessions` | 远端会话和设备令牌，支持撤销和过期 |
| `custody_manifests` | 加密备份 manifest，记录版本、对象摘要、前序版本和回滚计数 |
| `custody_recovery_drills` | 恢复演练记录，记录发起设备、结果、错误和审计 |
| `custody_rollback_events` | 检测到远端回滚、版本倒退或 checksum 不匹配时记录事件 |

#### API

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/public/passport/devices` | 设备目录 |
| `POST /api/v1/public/passport/devices/:deviceId/revoke` | 撤销设备 |
| `POST /api/v1/public/custody/manifests` | 写入新 manifest 版本 |
| `GET /api/v1/public/custody/manifests/latest` | 查询最新 manifest |
| `POST /api/v1/public/custody/manifests/verify` | 校验远端对象摘要和回滚计数 |
| `POST /api/v1/public/custody/recovery-drills` | 记录恢复演练 |

### 联调对象

- Wallet：提供设备确认 UI、本地加密格式版本、manifest 生成、恢复演练入口。
- Warehouse / 远端存储：保存对象内容，返回对象版本、checksum 和目录状态。
- Node：只保存 manifest、设备和审计，不保存明文私钥。

### 完成条件

- 新设备恢复、旧设备撤销、远端对象损坏、远端版本回滚和错误密码都有确定结果。
- Node 能发现并记录 manifest 回滚或 checksum 不匹配。
- 恢复演练可重复执行并形成审计记录。

## V2-M5：MPC 生产化决策

目标：明确 MPC 是否进入生产资产承诺；未通过前，Node MPC 只保持实验性协调服务。

### Node 交付

- 将现有 MPC 能力标记为实验性，并在 API / 文档 / UI 中避免生产资产承诺。
- 补齐 MPC session、participant、message、sign request、audit log 的风险标签和查询能力。
- 为安全评审提供导出材料：参与者、曲线、阈值、消息轮次、失败、恢复和审计。
- 等 Wallet、MPC 协调服务和安全评审确定生产方案后，再决定是否增加生产级状态机。

### 联调对象

- Wallet：门限、参与者、签名内容、恢复和用户责任展示。
- MPC 协调服务：协议互操作、掉线恢复、key refresh、故障注入。
- 安全评审：威胁模型、独立审计、高风险发现关闭。

### 完成条件

- 形成正式架构决策：进入生产、继续实验或不进入生产。
- 若进入生产，必须有成熟门限签名实现、独立审计、故障注入和恢复演练结果。

## 开发与联调顺序

### Phase 1：Passport 持久化与 PKCE

- 新增 Passport subject / binding / authorization request / code / audit 表。
- 实现 `/auth/passport/*` 最小闭环。
- 将 authorization code 从内存迁移到数据库。
- 加入 PKCE 校验。
- 删除旧 Passkey 独立入口，新联调只使用 `/auth/passport/*`。

### Phase 2：Passkey 无用户名登录与绑定恢复

- 已实现 subject 级 WebAuthn credential 存储。
- 已实现持久化 registration / authentication challenge。
- 已实现 discoverable credential 授权：`authorize/challenge -> authorize/approve` 不要求先输入钱包地址。
- 已实现 Passkey approve 复用 authorization code + PKCE 发码链路。
- 已实现安全解绑协议：钱包签名确认后由 Node 撤销钱包绑定、subject Passkey、授权请求/授权码并写审计。
- 待补钱包地址证明恢复 UI、安全通知和更完整审计展示。

### Phase 3：Scoped Grant

- 新增 grant 数据模型和 API。
- 收敛 central issuer session 边界。
- 与 Router / Warehouse 做 audience、capability、撤销和审计联调。

### Phase 4：设备与恢复

- 新增设备目录、设备撤销、manifest、回滚检测和恢复演练。
- 与 Wallet、Warehouse 联调加密备份与恢复流程。

### Phase 5：MPC 决策

- 输出 MPC 当前实验性边界。
- 准备安全评审材料。
- 根据评审结论决定是否进入生产化实现。

## 暂不进入 Node 的能力

| 能力 | 归属 |
| --- | --- |
| 安装、升级、失败回滚、卸载 | Agent Runtime |
| Runtime Task claim / heartbeat / report | Agent Runtime |
| 智能体实例状态、日志、健康检查、渠道连接 | Agent Runtime |
| Project 任务、文件、评论、成员和业务权限 | Project |
| 文件内容、对象存储、配额、复制、WebDAV / S3 数据面 | Warehouse |
| 模型路由、额度、计量和模型渠道 | Router |
| 钱包私钥、助记词、明文 share | Wallet |

如果后续 Node 需要参与这些流程，只提供目录、授权、release artifact、签名、审计或通知能力，不保存运行时主状态或密钥明文。
