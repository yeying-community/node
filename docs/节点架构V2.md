# 节点架构V2

本文记录 Node 后续体系化迭代方向。V2 只描述尚未实现、未完全实现或需要从 V1 能力中继续收敛的事项，避免和 [节点架构V1.md](./节点架构V1.md) 混在一起。

## 迭代原则

- Node 继续保持 Registry / Portal / Passport Provider 定位。
- 运行时能力不回流到 Node；Project 安装、升级、回滚、卸载和健康检查继续归 Agent Runtime。
- 文件内容和对象存储继续归 Warehouse，Node 只处理控制面元数据与授权。
- 模型调用、额度和计量继续归 Router。
- 每个 V2 能力落地前都应明确归属系统、状态所有者、调用方和审计边界。

## V2 待迭代能力

### 1. Registry / Release 能力增强

- Release artifact 下载接口和权限策略标准化。
- Release digest、签名、依赖声明、配置 schema 与 Agent Runtime 的稳定契约。
- Publisher key 管理页面和密钥轮换流程。
- Release 风险扫描、兼容性检查、撤回影响分析。
- 应用 / Skill / Tool / Agent Release 的统一目录模型。

### 2. Passport 与跨应用登录

- 手机相机扫码登录的 Passport 授权页。
- Project 作为 Node 已发布应用后的登录授权闭环。
- 一次性授权码、短期票据和 Project 登录态交换协议。
- Passkey、钱包、TOTP 多认证方式的统一授权确认体验。
- 应用 `redirectUri`、`audience`、`capabilities` 的管理端配置和审计展示。

参考专题：[YeYing-Passport-QRCode-Login.md](./YeYing-Passport-QRCode-Login.md)。

### 3. UCAN 策略产品化

- 应用级 capability 模板。
- 用户授权确认页和授权记录查询。
- UCAN 委托链可视化和撤销体验。
- 钱包签发模式与中心化 issuer 模式的统一 SDK。
- 多后端 audience 策略和最小权限建议。

### 4. 通知中心二期

- 通知模板和订阅偏好。
- 管理员广播。
- Webhook delivery 监控、批量重试、死信处理和签名验收规范。
- 邮件、短信或社区其他通知出口。
- 通知事件统一接入审核、授权、MPC、release、系统状态和安全事件。

### 5. 审核治理增强

- 多级审批、策略化审批人、自动审批条件。
- 审核 SLA、过期提醒和升级处理。
- 审核证据、风险标签和操作审计报表。
- 应用、release、publisher key、权限变更的统一审核模型。

### 6. MPC 协调器增强

- 更完整的 session 状态机和异常恢复。
- Redis Streams 消费组与跨实例恢复策略。
- 签名请求审计查询和问题定位工具。
- 会话级权限、参与者隔离和更细粒度能力控制。

### 7. 运维与平台工程

- OpenAPI 分组和 SDK 发布自动化。
- 运行配置校验和启动前诊断。
- 数据库 migration dry-run / rollback 演练流程。
- 指标、日志、审计和告警统一规范。
- 安全基线检查：CORS、JWT、UCAN、Passkey、TOTP、Webhook 签名和密钥托管。

### 8. 文档治理

- 将稳定能力沉淀到 V1，未落地能力保留在 V2。
- 减少历史文档和重复说明，避免 `接口说明.md` 与 OpenAPI 字段双写。
- 将跨仓库边界优先引用社区统一文档：[社区产品关系与开发边界](https://github.com/yeying-community/books/blob/main/yeying/%E7%A4%BE%E5%8C%BA%E4%BA%A7%E5%93%81%E5%85%B3%E7%B3%BB%E4%B8%8E%E5%BC%80%E5%8F%91%E8%BE%B9%E7%95%8C.md)。

## 暂不进入 Node 的能力

| 能力 | 归属 |
| --- | --- |
| 安装、升级、失败回滚、卸载 | Agent Runtime |
| Runtime Task claim / heartbeat / report | Agent Runtime |
| 智能体实例状态、日志、健康检查、渠道连接 | Agent Runtime |
| Project 任务、文件、评论、成员和业务权限 | Project |
| 文件内容、对象存储、配额、复制、WebDAV / S3 数据面 | Warehouse |
| 模型路由、额度、计量和模型渠道 | Router |

如果后续 Node 需要参与这些流程，应只提供目录、授权、release artifact、签名、审计或通知能力，不保存运行时主状态。
