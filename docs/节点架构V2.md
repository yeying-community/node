# 节点架构V2

本文记录 Node 下一阶段的钱包身份、授权和恢复路线。V2 的核心目标是让 Node 承担钱包身份 Issuer、应用授权码服务、UCAN issuer、MPC 协调和托管密钥控制面职责。

## 当前判断

Node 不再维护独立 Passport subject。新的身份模型统一为钱包身份 DID：

- 身份主键：`did:yeying:wid_*`
- 钱包地址：钱包身份下的链账户关联
- 用户名和邮箱：钱包身份下的 `UsernameCredential` / `EmailCredential`
- 通行证：无钱包插件场景下的 Passkey 认证器入口

Web3 应用只接入 `/api/v1/public/identity/*`。Router 等需要邮箱的应用必须请求 `identity.email`，并在缺少已验证邮箱时提示用户先在钱包插件完成钱包身份和邮箱验证。

## 设计原则

- Node 不拥有钱包身份私钥，只验证和签发身份凭证。
- Web3 应用不得实现钱包、通行证或身份绑定逻辑。
- 认证和授权分离：Passkey / Wallet presentation 解决“谁控制该钱包身份”，scopes / UCAN 解决“能访问什么”。
- 应用只能拿到短期 authorization code 和按 scopes 授权的钱包身份结果。
- 授权、设备、恢复和撤销必须可审计、可回放、可测试。

## V2-M2：钱包身份授权

目标：Node 支持钱包身份账户关联、邮箱/用户名凭证、身份级 Passkey，以及 `authorization code + PKCE(S256)` 的 Web3 应用登录。

### 数据模型

| 表 | 目的 |
| --- | --- |
| `identity_account_link_challenges` | 持久化钱包身份与链账户关联 challenge |
| `identity_account_links` | 钱包身份 DID 与链账户地址的已验证关联 |
| `identity_verifications` | 邮箱/用户名验证事务 |
| `identity_credentials` | 已签发的钱包身份凭证 |
| `identity_passkey_credentials` | 钱包身份级 WebAuthn credential |
| `identity_webauthn_challenges` | WebAuthn registration / authentication challenge |
| `identity_authorization_requests` | 应用身份授权请求 |
| `identity_authorization_codes` | 一次性授权码 |

### API

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/public/identity/account-links/challenge` | 创建钱包身份与链账户关联 challenge |
| `POST /api/v1/public/identity/account-links/verify` | 校验身份控制器签名和账户签名 |
| `POST /api/v1/public/identity/verifications/request` | 请求邮箱/用户名验证 |
| `POST /api/v1/public/identity/verifications/confirm` | 确认验证码并签发凭证 |
| `POST /api/v1/public/identity/passkeys/register/request` | 创建身份级 Passkey 注册请求 |
| `POST /api/v1/public/identity/passkeys/register/confirm` | 保存身份级 Passkey credential |
| `POST /api/v1/public/identity/authorize/request` | 应用发起 code + PKCE 授权请求 |
| `GET /api/v1/public/identity/authorize/request/:requestId` | 查询授权请求公开信息 |
| `POST /api/v1/public/identity/authorize/challenge` | 针对请求生成 WebAuthn assertion options |
| `POST /api/v1/public/identity/authorize/approve` | 用 Wallet presentation 或 Passkey assertion 批准授权 |
| `POST /api/v1/public/identity/authorize/exchange` | 校验 code 与 PKCE，返回授权的钱包身份结果 |

### 关键约束

- WebAuthn 注册和认证必须校验 RP ID、origin、challenge、credential 状态和用户验证结果。
- 日常登录支持 discoverable credential，不要求用户先输入钱包地址。
- code 必须一次性、短期、持久化，并绑定 `appId`、`redirectUri` 和 `codeChallenge`。
- `authorize/exchange` 必须校验 PKCE `codeVerifier`。
- exchange 结果只返回授权 scopes 内的钱包身份 DID、钱包地址和凭证，不返回 Passport assertion 或应用侧绑定结果。

## V2-M3：授权与资源访问

- 收敛 central issuer session 边界。
- 将 Router / Warehouse 等服务的 audience、capabilities、撤销和审计联调纳入验收。
- Web3 应用侧复用 web3-bs 的钱包身份登录组件和授权结果校验逻辑。

## V2-M4：设备与恢复

- Wallet 负责身份私钥、设备目录和用户确认体验。
- Node 负责已验证身份凭证、身份级 Passkey、托管密钥恢复门禁和安全审计。
- 恢复流程必须要求钱包身份认证或地址控制证明，不得降级为应用侧绑定。

## V2-M5：MPC 生产化决策

- 明确门限、参与者、签名内容、恢复和用户责任展示。
- 验证 MPC 协议互操作、掉线恢复、key refresh 和故障注入。
- 形成正式架构决策：进入生产、继续实验或不进入生产。
