# 身份凭证生命周期与授权设计

## 目标

身份验证事实和短期出示凭证必须分层管理。邮箱、用户名、头像和钱包账户的验证完成后，验证事实持续保存在 Node；JWT-VC 只承担短期出示和跨系统传输职责。JWT-VC 过期不能等同于验证事实失效。

本设计保留以下 scope：

```text
identity.basic
identity.email
identity.username
identity.wallet
identity.avatar
```

## 数据分层

### 长期验证事实

长期事实由 Node 的身份记录维护，并以撤销状态作为硬边界：

- Email/Username/Avatar：以未撤销的历史凭证记录及其声明作为已验证事实；
- Wallet：以未撤销的 `identity_account_links` 账户关联记录作为账户事实；
- Passkey：只证明当前设备持有该身份的认证器，不改变邮箱、头像等事实内容。

长期事实不能因为短期 JWT-VC 过期而自动删除或变为未验证。明确撤销、账户解绑、身份禁用后，事实不可通过普通登录自动恢复。

### 短期出示凭证

JWT-VC 默认短期有效，最长不超过配置允许的期限。授权交换时只返回请求 scope 对应的未撤销且未过期凭证。过期凭证可以根据长期事实重新签发新的 JWT-VC，新的凭证使用新的 `credentialId`，并记录审计日志。

JWT-VC 使用 `EdDSA` 签名，header 的 `kid` 必须与 issuer JWKS 一致；默认有效期 24 小时，最长 7 天。签发私钥只能从加密 vault（`run/secrets.enc.json`）解密读取，不能写入 `config.js` 或提交仓库。issuer 的非敏感参数（`enabled`、`baseUrl`、`usernameNamespace`）放在 `config.js` 的 `issuer.identity`。

## 统一确保流程

所有身份授权入口必须调用同一个凭证确保服务：

```text
验证认证方式（Passkey 或身份控制器 presentation）
→ 校验身份、账户链接和撤销状态
→ 计算请求 scope 对应的凭证类型
→ 复用有效 JWT-VC；缺失或过期时基于长期事实续签
→ 写入审计日志
→ 签发授权码
```

Passkey 授权和二维码/钱包 presentation 授权都使用该流程。显式 `reissue/challenge` API 继续保留，用于钱包主动刷新和需要明确 controller proof 的场景，但不再复制凭证签发逻辑。`reissue/confirm` 必须提交带 `manage` proof 的身份文档，并用当前 identity controller 对 challenge canonical payload 生成 `YeyingCredentialReissueProofV1`；Node 只基于未撤销的既有记录重签同类型短期 JWT-VC，不接受仅凭 DID 直接重签。凭证状态以 `identity_credentials` 数据库为权威：未知返回 `unknown`、过期返回 `expired`、撤销/替换按记录返回，状态查询失败返回 503 且不得降级为 `active`。

确保服务必须满足：

- 只从未撤销的历史事实或 active 钱包账户链接续签；
- 已撤销、已解绑或没有历史事实时返回原有 `*_REQUIRED` 错误；
- 一次请求中按类型批量处理，尽量在单个事务中完成；
- 续签前后重新检查最新有效凭证，避免并发请求无限生成重复凭证；
- 每次自动续签记录身份、凭证类型、来源和新凭证 ID，不记录邮箱等敏感值。

## 安全边界

Passkey 或身份 presentation 只能恢复已经存在的身份事实，不能创建新的邮箱验证、钱包绑定或控制器权限。

- 普通登录：允许恢复过期的 Email、Username、Avatar 和 WalletAccount JWT-VC；
- 修改邮箱、找回账户、钱包恢复、转账、解绑和撤销等敏感操作：必须再次执行对应的邮箱验证码、钱包签名或 step-up 授权；
- 已撤销的凭证和已解绑的钱包账户不能通过自动续签恢复；
- `identity.avatar` 是身份资料 scope，继续参与授权和凭证返回，但不能单独作为高风险操作的认证依据；
- `authorize/exchange` 的 `ucanSession` 仅在请求显式传入 `issueUcanSession: true` 时返回，是短期、不透明的资源授权会话，不是身份凭证或 JWT；
- 刷新令牌只在数据库保存 SHA-256 哈希，默认有效期 30 天（`identity.session.refreshTtlMs`，最大 180 天），不是 UCAN，也不能直接访问 Router 或 WebDAV；`ucanSession` 到期后调用 `session/refresh` 轮换，登出时调用 `session/revoke` 并清理本地刷新令牌。

## 一致性与运维

凭证确保和授权记录应保持可审计。凭证续签失败时不得降级为旧的过期凭证，也不得把状态查询失败当成 active。生产环境应监控续签失败率、重复续签率和撤销后的拒绝情况，并定期清理过期且不再需要的历史 JWT-VC（不得清理长期事实或审计记录）。

## 兼容策略

现有客户端无需改变 scope 或重新完成验证。客户端仍按授权交换返回的 JWT-VC 使用，并通过 issuer、JWKS 和 status 接口校验。新实现只改变 Node 在授权前补齐短期凭证的方式，不移除 `identity.avatar`，也不恢复旧 Passport 字段。

该模块不替代普通 SIWE：DApp 不请求身份 scope 时，仍只走原有 SIWE challenge/verify 流程，Node 不参与身份资料获取。钱包身份 issuer 独立于旧 Passport，不创建、不解析、不返回 `subjectId` 或 `sub_xxx`。

## 接口契约

身份 issuer、凭证、账户关联、Passkey/TOTP 和授权码等端点的请求/响应结构以 OpenAPI 为准：[`docs/openapi/node.openapi.yaml`](./openapi/node.openapi.yaml) 的 `Identity` tag（含 `/.well-known/jwks.json`、`/.well-known/openid-credential-issuer` 和 `/api/v1/public/identity/*`）。`authorize/exchange` 的响应结构见 `IdentityAuthorizeExchangeResult` schema。
