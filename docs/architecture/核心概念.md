# Node 核心概念

本文集中解释 Node 身份、登录授权和云端托管中反复出现的术语，并列出中英文全称和简称。后续文档可以直接使用简称；Node 登录和应用登录协议分别以[Node登录授权](../identity/Node登录授权.md)、[DApp登录授权](../identity/DApp登录授权.md)为准；凭证生命周期和安全边界分别见[身份凭证](../identity/身份凭证.md)和[通行密钥](../identity/通行密钥.md)。没有通用简称或对应名称时以 `—` 标记。

## 身份与认证器

| 中文全称 | 中文简称 | 英文全称 | 英文简称 | 在 Node 中的含义 |
| --- | --- | --- | --- | --- |
| 去中心化标识符 | DID | Decentralized Identifier | DID | Wallet Identity 的稳定身份主体，当前形式如 `did:yeying:wid_*`。邮箱、用户名、钱包地址和 Passkey 都不是 DID。 |
| 身份控制器 | — | Controller | — | 持有 DID 文档中对应私钥的一方，可按密钥用途管理身份或签署 Presentation。Node 只验证公开密钥和签名，不持有用户 controller 私钥。 |
| 认证器 | — | Authenticator | — | 执行认证操作的设备或软件，例如平台认证器、安全密钥或 TOTP 应用。认证器可创建或持有认证凭证；认证器绑定 DID，但不等于 DID controller。 |
| Web 身份验证 | — | Web Authentication | WebAuthn | W3C 标准化的浏览器 API 与身份验证协议，使网站能够通过浏览器调用认证器创建和使用公钥凭证。注册使用 `create`，认证使用 `get`；RP ID、origin 和一次性 challenge 将操作绑定到服务与本次请求。文档首次出现时写“Web 身份验证（Web Authentication，简称 WebAuthn）”，后文使用 WebAuthn。 |
| 通行密钥 | — | Passkey | — | WebAuthn 凭证，由认证器创建或持有；认证器通过公钥签名证明 Passkey credential 控制权。Node 保存 credential ID、公钥及状态，不保存 credential 私钥。 |
| 依赖方标识符 | — | Relying Party Identifier | RP ID | 使用 WebAuthn 的服务域名边界。Node 在 Passkey 登录中作为 RP；浏览器根据 RP ID/origin 限定凭证的适用范围。 |
| WebAuthn 认证断言 | — | WebAuthn Authentication Assertion | Assertion | 认证器对 challenge 等上下文生成的签名响应。它证明 credential 控制权，不包含 Passkey 私钥，也不是钱包交易签名。 |

### 可验证身份资料

| 中文全称 | 中文简称 | 英文全称 | 英文简称 | 在 Node 中的含义 |
| --- | --- | --- | --- | --- |
| 可验证凭证 | VC | Verifiable Credential | VC | Node 当前以 JWT-VC 格式签发身份资料凭证，例如 `EmailCredential`、`UsernameCredential`、`AvatarCredential` 和 `WalletAccountCredential`。VC 说明某个 DID 的资料或关联已经验证过；接收方仍须检查 issuer、签名、subject、有效期和凭证状态。 |
| 凭证签发者 | — | Issuer | — | Node 身份 Issuer 验证资料并签署 VC；应用需验证签名和 issuer 信任。 |
| 凭证主体 | — | Subject | — | VC 描述的主体。夜莺身份 VC 的 subject 通常是 Wallet Identity DID。 |
| 身份出示结果 | — | Identity Presentation | Presentation | 面向特定请求的一次性身份出示结果。Wallet 插件路径由 DID controller 签名，并绑定 audience、nonce、scope 和有效期；Node Passkey 路径则由 Node 验证 assertion 后签发授权码。 |
| 授权范围 | — | Scope | — | 应用请求的权限范围。身份 scope（如 `identity.email`）决定可以返回哪些身份资料；scope 本身不是密钥或会话。 |

VC 不是私钥、登录会话或资源授权。Passkey 登录不会自动把所有 VC 交给应用；应用须请求相应 scope，Node/Wallet 只提供获准且有效的资料。

## 登录与授权

| 中文全称 | 中文简称 | 英文全称 | 英文简称 | 在 Node 中的含义 |
| --- | --- | --- | --- | --- |
| 身份认证 | 认证（AuthN） | Authentication | AuthN | 确认某个认证因素或身份控制证明有效，例如验证 WebAuthn assertion，或验证 DID controller 对 Presentation 的签名。 |
| 访问授权 | 授权（AuthZ） | Authorization | AuthZ | 决定认证通过后允许访问哪些资料或资源。通过应用登记、用户确认、scope、audience 和 UCAN capability 等条件限制。认证成功不等于所有操作都获准。 |
| 一次性挑战值 | 挑战值 | Challenge | — | 防止旧签名或断言重放；须绑定请求、设置有效期并在成功后消费。 |
| 一次性随机值 | 随机值 | Nonce | — | 将身份 Presentation 或授权请求绑定到单次会话/请求上下文。 |
| 请求关联值 | 状态值 | State | — | DApp/Router 将回调和原始登录会话对应起来，防止回调串线或登录 CSRF。 |
| 授权码 | — | Authorization Code | Code | Node 在用户批准身份请求后签发，应用后端用它兑换按 scope 批准的身份结果；它不是长期访问令牌。 |
| 授权码交换证明密钥 | — | Proof Key for Code Exchange | PKCE | 应用先生成 verifier，再向 Node 提交其 S256 challenge；兑换时提交 verifier，证明兑换方持有原请求的秘密。Verifier 应由应用后端安全保存。 |
| 应用会话 | App Session | Application Session | App Session | Router/DApp 在兑换成功后自己建立的登录状态。它属于该应用，不是通用 DID 控制权或钱包密钥。 |
| 目标受众 | 受众 | Audience | — | 令牌或证明的目标接收方，限制身份 Presentation、UCAN 或恢复 token 能在哪个应用/服务使用。接收方必须精确检查 audience。 |
| 用户控制授权网络 | UCAN | User Controlled Authorization Network | UCAN | 用能力（capability）表达主体对特定 audience/resource/action 的授权。UCAN 是资源访问授权凭证，不是 VC、Passkey 或钱包私钥。 |

## 云端与恢复

| 中文全称 | 中文简称 | 英文全称 | 英文简称 | 在 Node/Wallet 中的含义 |
| --- | --- | --- | --- | --- |
| 通行密钥同步服务 | — | Passkey Synchronization Service | Passkey Sync | Apple、Google、Microsoft 等平台可提供认证器凭证同步能力；Node 作为 RP 看不到凭证私钥，也不控制平台账户。 |
| 夜莺云端钱包托管 | 钱包托管 | YeYing Cloud Custody | Cloud Custody | 托管服务保存 Wallet 加密后的密钥材料密文。服务端不能解密；它与平台 Passkey 同步服务是两种独立系统。 |
| 托管写入能力 | `custody.write` | Custody Write Capability | `custody.write` | 写入或更新用户托管密文的资源能力，只授权对应托管写操作。 |
| 托管恢复能力 | `custody.recovery` | Custody Recovery Capability | `custody.recovery` | 受限的托管恢复读取授权。Node 在身份授权成功后签发短期 token；Wallet 还必须使用原钱包密码在本地解密密文。 |
| WebAuthn 跨设备认证传输 | Hybrid | WebAuthn Hybrid Transport | Hybrid | 使用附近手机等远端认证器完成一次 WebAuthn 操作的浏览器/系统流程。二维码界面由浏览器和操作系统决定；hybrid hint 是偏好，不保证特定 UI，也不代表 YeYing Cloud 参与认证。 |

恢复托管密钥通常需要两个独立条件：Node 验证绑定认证器并签发 `custody.recovery` 读取授权；用户提供原钱包密码，由 Wallet 本地解密。邮箱 OTP、普通应用会话或单独的 Passkey assertion 都不能替代这两步。
