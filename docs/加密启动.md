# 密钥初始化与加密启动

Node 运行时只使用加密密钥仓 `run/secrets.enc.json` 保存敏感材料，不使用根目录 `.env` 或业务环境变量传递密钥。

## 密钥模型

- `ISSUER_PRIVATE_KEY`：Node 统一 Issuer 的 Ed25519 私钥。它决定 Issuer 公钥、`kid` 和由 `issuer.baseUrl` 派生的 DID。
- `ISSUER_PRIVATE_KEY_NEXT`、`ISSUER_PRIVATE_KEY_PREVIOUS`：Issuer 密钥轮换窗口的可选密钥。`NEXT` 只发布并信任，`PREVIOUS` 只用于验证旧 token；两者不是 `secrets:verify` 的必填项。
- `NODE_KEY_DERIVATION_SECRET`：Node 内部派生根。JWT、TOTP 存储和通知 Webhook 分别使用固定用途上下文派生，不再配置多份用途密钥。
- `DATABASE_USERNAME`、`DATABASE_PASSWORD`：数据库凭据。
- `REDIS_USERNAME`、`REDIS_PASSWORD`：启用 Redis 时使用的凭据。
- `MAIL_SMTP_USER`、`MAIL_SMTP_PASSWORD`：启用邮件发送时使用的凭据。
- `ADMIN_DIDS`：首次治理 bootstrap 白名单，使用 `./cmd admin allow` 写入，不通过环境变量注入。

## 初始化和更新

首次初始化：

```bash
./cmd secrets init
```

写入或轮换单项密钥：

```bash
./cmd secrets set DATABASE_USERNAME
./cmd secrets set DATABASE_PASSWORD
./cmd secrets set ISSUER_PRIVATE_KEY
./cmd secrets set NODE_KEY_DERIVATION_SECRET
./cmd admin allow add 0x你的钱包地址
```

轮换窗口密钥按需写入 vault：

```bash
./cmd secrets set ISSUER_PRIVATE_KEY_NEXT
./cmd secrets set ISSUER_PRIVATE_KEY_PREVIOUS
```

修改 vault 解密密码：

```bash
./cmd secrets passwd
```

`passwd` 会保留所有密钥值，仅把 `secrets.enc.json` 用新密码重新加密。生产执行前应先备份 vault 文件，并在下一次启动时使用新密码准备一次性 `secrets.passwordFile` 或从终端输入新密码。

初始化和更新都会使用 `AES-256-GCM + PBKDF2` 加密 vault，并将文件权限设为 `0600`。生产环境不得执行 `secrets:init --force` 覆盖现有 vault。

## 启动

在 `config.js` 中配置：

```js
secrets: {
  file: '/opt/deploy/node/run/secrets.enc.json',
  passwordFile: '/opt/deploy/node/run/.secrets-password'
}
```

启动脚本会同时读取 `NODE_ENV` 和 `config.js` 的 `app.env` 判断运行环境：任一值为 `production` 时按生产处理；否则按开发/测试处理。

开发/测试环境会保留并复用 `secrets.passwordFile`，便于升级或重启时自动拉起：

```js
app: {
  env: 'test'
}
```

```bash
NODE_ENV=test ./cmd service restart
```

生产环境会把 `secrets.passwordFile` 当作一次性密码文件：如果文件已存在，启动时复用该文件并在启动后清理；如果文件不存在，则从终端输入 vault 密码，脚本只在启动期间写入临时密码文件，Node 解密后仅在进程内存中使用并清理密码文件：

```bash
./cmd service restart
```

校验 vault 只输出密钥名称，不输出密钥值：

```bash
./cmd secrets verify
./cmd secrets unlock
```

## 生产注意事项

- `ISSUER_PRIVATE_KEY` 和 `NODE_KEY_DERIVATION_SECRET` 必须在生产备份中保留。
- 不要直接覆盖正在使用的统一 Issuer 私钥。轮换必须先发布 `ISSUER_PRIVATE_KEY_NEXT`，再提升为 active，并在窗口内保留 `ISSUER_PRIVATE_KEY_PREVIOUS`。
- `ISSUER_PRIVATE_KEY_NEXT` 和 `ISSUER_PRIVATE_KEY_PREVIOUS` 是可选项；完成轮换且旧 token 全部过期、下游 JWKS 缓存已刷新后，才可以删除 `ISSUER_PRIVATE_KEY_PREVIOUS`。
- 不要更换派生根，否则历史 JWT、TOTP 密文和 Webhook 密文将无法按原用途派生。
- 轮换 Issuer 私钥前，必须先实现历史公钥 JWKS 保留；轮换派生根前，必须先实现历史密文重新加密迁移。
- 密钥 vault 应纳入主机级备份，但绝不能提交到 Git、写入日志或复制到 `config.js`。
